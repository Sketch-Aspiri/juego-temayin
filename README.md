# Temayin - La Aventura del Jaguar

Juego de plataformas 2D con **React + TypeScript + Canvas**. React gestiona menús, HUD, pausa, progreso y ajustes; un motor de juego independiente (sin dependencias de React) simula y dibuja el nivel en un `<canvas>`.

## Comandos

Camazotz cuenta con ocho poses nuevas, 15 PV y tres fases reforzadas: picadas encadenadas, lluvias dirigidas, seis ecos y rayos dobles o triples. Detalles y controles en [la guía del Mundo 7](src/data/levels/world7/README.md).

```bash
npm install
npm run dev        # servidor de desarrollo
npm run build      # typecheck + build de producción en dist/
npm test           # pruebas (vitest)
```

## Controles

| Acción | Teclado |
|---|---|
| Mover | ← → / A D |
| Saltar | Espacio / ↑ / Z |
| Correr | Shift / X |
| Bola de fuego (con chile) | C / F / J |
| Pausa / Silencio | P o Esc / M |

En **Ajustes** puedes reasignar las teclas de movimiento, salto, carrera, fuego/pelota, pausa y silencio. Pulsa el botón de una acción y luego su nueva tecla; Esc cancela. Se detectan teclas ocupadas y puedes restaurar el teclado original. Esc siempre permite pausar.

Los botones táctiles permiten ajustar tamaño (80–120 %), opacidad (40–100 %) y colocar el movimiento a la izquierda o a la derecha, con vista previa. Las preferencias se guardan entre sesiones y se pueden restaurar. **Correr** se activa o desactiva con un toque; no hay que mantenerlo pulsado. Se pueden combinar dirección, salto y fuego con varios dedos y deslizar entre botones sin levantar el dedo. El mando cancela los gestos de zoom para que los saltos rápidos no amplíen la pantalla. Al pausar o salir se liberan los controles.

## Arquitectura

```
src/
  engine/            Motor (TypeScript puro, sin React)
    World.ts         Estado y reglas de un nivel (testeable sin DOM)
    Game.ts          Bucle de tiempo fijo, muertes, fin de nivel
    entities/        jugador, enemigos (registro), objetos, proyectiles
    bosses/          interfaz Boss + registro + Púas
    level/           DSL de niveles y constructor de mapas
    render/          Renderer, texturas, fondos, temas, sprites
  data/              Contenido: niveles y mundos (aquí se añade contenido)
  store/             Zustand: progreso, ajustes, persistencia (localStorage)
  ui/                Pantallas y componentes React
```

El motor publica a React un `HudState` solo cuando cambia, por lo que la interfaz no se re-renderiza en cada fotograma.

## Cómo ampliar el juego

**Nuevo nivel:** crea un `LevelDef` en `src/data/levels/` y añádelo a un mundo en `src/data/worlds.ts`. El selector, el desbloqueo, las estrellas y el guardado funcionan solos. Las operaciones del DSL (`pit`, `row`, `plat`, `coins`, `pipe`, `stairs`, `col`, `wall`, `flag`, `temple`, `spawn`) están documentadas en `engine/level/types.ts`. `npm test` valida que cada nivel sea coherente (hoyos cruzables, enemigos sobre suelo, meta alcanzable...).

**Nuevo mundo:** añade un objeto a `WORLDS`.

**Nuevo enemigo:** añade su id en `engine/types.ts`, su definición en `ENEMIES` (`entities/enemies.ts`) y su dibujo en `render/sprites.ts`.

**Nuevo tema visual:** añade su id en `ThemeId`, su escenario en `render/backgrounds.ts` y regístralo en `render/themes.ts`.

**Nuevo jefe:** implementa la interfaz `Boss` (`bosses/types.ts`), añade su id a `BossId` y regístralo en `bosses/index.ts`.

- **Bolsa persistente:** el cacao se guarda al recogerlo y se conserva entre niveles, al morir, al perder todas las vidas y al cerrar el juego. Las vidas se compran; se elimina la conversión automática de 100 cacao. La bolsa aparece en el HUD y el selector. Las compras pendientes sobreviven si se cierra el encuentro antes de empezar. Al continuar se consumen; fuego y escudo se pierden según las reglas normales de daño y muerte. Reaparecer no reabre la tienda, reiniciar el nivel sí. Las estrellas siguen dependiendo del cacao recogido en el nivel. Los guardados v3 anteriores y v2 migrados conservan sus récords y comienzan con bolsa vacía; borrar progreso vacía también la bolsa.

El arte fuente está en `imagenes/`; los sprites usados por el juego en `public/assets/`. La versión original en un único `index.html` queda en el historial de git.

La limpieza de recursos conserva los originales utilizados por importadores, catálogo y pruebas, sus prompts y atlas, las licencias y todo el material de Hanal Pixán. Se retiraron PNG de servicio duplicados, variantes descartadas, copias históricas y capturas e informes generados. Los scripts `imagenes/verify_*.py` vuelven a producir las evidencias en las carpetas indicadas más arriba; se conservan los resúmenes Markdown de las revisiones.

La biblioteca de arte incluye imágenes de enemigos, jefes, personajes, paisajes, objetos, complementos, proyectiles y decorados de arenas. Consulta [la galería](imagenes/galeria.html), [el catálogo](imagenes/catalogo.json) y [las instrucciones de arte](imagenes/PLAN_ARTE.md) para revisar los PNG, los prompts y los recortes; los recursos nuevos del Mundo 6 están documentados en [su revisión visual](imagenes/verificacion/mundo6/REVISION.md) y los del final en [los prompts del Mundo 7](imagenes/nuevos/mundo7/PROMPTS.md). `python imagenes/verify_gameplay_sprites.py` comprueba la integración general con Vite en el puerto 5197.
